# Решение проблемы потери соединения ADB при перезагрузке Алисы

## Проблема

При перезагрузке Алисы (Yandex Station Lite) теряется соединение ADB, и управление голосом перестает работать. Это происходит потому, что:

1. При перезагрузке устройства сбрасывается сессия ADB
2. Процесс моста продолжает работать, но не может читать логи Quasar
3. Нет механизма автоматического восстановления соединения

## Решение

Мы реализовали двухступенчатую систему восстановления соединения ADB:

### 1. Мониторинг соединения ADB (scripts/monitor_adb_connection.sh)

Новый скрипт мониторинга, который:
- Периодически проверяет состояние соединения ADB
- Автоматически восстанавливает соединение при его потере
- Перезапускает мост при успешном восстановлении соединения
- Логирует все действия для отладки

**Параметры:**
- `CHECK_INTERVAL=30` - интервал проверки состояния соединения (секунды)
- `MAX_RETRIES=5` - максимальное количество попыток восстановления соединения

### 2. Улучшенная обработка ошибок в Python-скрипте (station_music/watch.py)

Обновленный скрипт `watch.py` теперь:
- Проверяет состояние процесса ADB на каждом шаге чтения
- Выбрасывает исключение `BridgeError` при неожиданном завершении процесса ADB
- Позволяет скрипту мониторинга перезапустить мост при потере соединения

### 3. Обновленный основной скрипт (scripts/run_voice_bridge.sh)

Основной скрипт теперь запускает скрипт мониторинга вместо прямого запуска моста.

## Как это работает

1. **Запуск**: `run_voice_bridge.sh` запускает `monitor_adb_connection.sh`
2. **Мониторинг**: `monitor_adb_connection.sh` проверяет состояние ADB каждые 30 секунд
3. **Потеря соединения**: Если соединение lost, скрипт пытается восстановить его
4. **Восстановление**: При успешном восстановлении соединения перезапускается мост
5. **Ошибка**: Если восстановление не удается, скрипт ждет 60 секунд и пытается снова

## Установка и настройка

1. **Создайте файл конфигурации** (если еще не создан):
   ```bash
   mkdir -p work
   cp .env.example work/installation.env
   ```

2. **Настройте параметры** в `work/installation.env`:
   ```bash
   STATION_ADB_SERIAL="192.168.0.72:5555"  # Ваш IP станции
   HA_URL="https://ваш-home-assistant"
   HA_TOKEN="ваш-токен"
   MA_CONFIG_ENTRY_ID="ваш-id"
   MA_PLAYER_ENTITY="media_player.station_lite_ma"
   YT_PROVIDER="ytmusic"
   ```

3. **Создайте файл с токеном HA** (если еще не создан):
   ```bash
   mkdir -p work
   echo "ваш-токен-HA" > work/ha_token
   chmod 600 work/ha_token
   ```

4. **Запустите мост**:
   ```bash
   ./scripts/run_voice_bridge.sh
   ```

## Логирование

Скрипт мониторинга выводит подробные логи:
- Время начала мониторинга
- Уведомления о потере соединения
- Результаты попыток восстановления
- Уведомления о перезапуске моста

Пример лога:
```
Mon Jan 01 12:00:00 UTC 2024: Starting ADB connection monitor for 192.168.0.72:5555
Mon Jan 01 12:05:00 UTC 2024: ADB connection lost. Attempting to reconnect...
Mon Jan 01 12:05:05 UTC 2024: ADB reconnected successfully
Mon Jan 01 12:05:05 UTC 2024: Restarting voice bridge...
```

## Отладка

Если проблема persists, проверьте:

1. **Состояние ADB**:
   ```bash
   adb devices
   ```

2. **Логи мониторинга**: Запустите скрипт вручную и наблюдайте за логами
   ```bash
   ./scripts/monitor_adb_connection.sh 192.168.0.72:5555 ./scripts/run_voice_bridge.sh
   ```

3. **Соединение с устройством**: Убедитесь, что устройство доступно в сети

4. **Права доступа**: Убедитесь, что ADB имеет необходимые права на устройстве

## Преимущества решения

1. **Автоматическое восстановление**: Нет необходимости вручную перезапускать мост
2. **Надежность**: Система продолжает работать даже при кратковременных сбоях сети
3. **Логирование**: Легко диагностировать проблемы при их возникновении
4. **Безопасность**: Нет изменений в прошивке устройства или настройках Алисы
5. **Совместимость**: Работает с существующей инфраструктурой Home Assistant и Music Assistant

## Ограничения

1. **Время восстановления**: Восстановление соединения может занять до 60 секунд
2. **Потеря команд**: Команды, данные во время потери соединения, могут быть lost
3. **Сетевые проблемы**: Длительные сетевые сбои могут привести к необходимости ручного вмешательства
